# Requirements: v1.2 Greg AI Enhancement

Turns the shipped Greg AI chatbot (persistent per-user chat, Haiku 4.5, Socratic tutor) into a
differentiated, cost-safe tutoring product. All requirements build on the existing
`gregAiWidget.tsx` + `api.greg-ai.tsx` + `gregChat.prisma.ts` foundation.

Priority: **P0** = pre-launch/blocking, **P1** = high value, **P2** = differentiator/later.

| ID | Priority | Requirement | Rationale |
|----|----------|-------------|-----------|
| GREGAI-01 | P1 | Students can attach a **photo** of an exercise (camera or file) and Greg AI reasons over the image. | #1 wow feature — students photograph problems instead of typing LaTeX. |
| GREGAI-02 | P0 | Enforce a **per-user daily message quota** (persisted, survives serverless restarts) with a friendly limit message. | Protects the Anthropic bill before launch; in-memory rate limit alone is insufficient on Vercel. |
| GREGAI-03 | P1 | Students can rate each assistant message **👍/👎**, stored with the chat history. | Cheap; produces evidence to tune the prompt and A/B model tiering. |
| GREGAI-04 | P1 | On content pages, seed the chat with a **context-aware opener** and pass the exact exercise/topic into the system prompt. | Greg AI knows what the student is looking at instead of guessing. |
| GREGAI-05 | P1 | Explicit **hint-ladder UX** (hint → another hint → show solution), each step a hidden directive; hint depth is logged. | Makes the Socratic progression a real UX contract, not prompt-only; enables per-topic difficulty analytics. |
| GREGAI-06 | P2 | Greg AI can **search site content** (exercises, videos, books) via tools and recommend real links in its answers. | Converts the tutor from a cost center into a funnel toward content and paid books. |
| GREGAI-07 | P2 | Inject a one-line **student profile** (level, completed/struggled units) from `UserProgress` into the system prompt; optionally let Greg AI write observations back. | Difficulty and references adapt automatically; lightweight long-term memory. |
| GREGAI-08 | P2 | **Practice mode**: generate N problems on a topic as structured data, render as exercise cards, check answers step by step. | Active practice loop; reuses exercise-card UI instead of chat text. |
| GREGAI-09 | P2 | **Teacher analytics** admin page aggregating chat sessions by topic, hint depth, and give-up points. | Tells Greg (the human) what videos/exercises to make next. Requires privacy-policy disclosure. |
| GREGAI-10 | P1 | **Model tiering**: route to a stronger model (e.g. Opus) when an image is attached or the conversation exceeds N turns; keep Haiku for the easy majority. | Quality where it matters (multi-step Λύκειο problems) without paying Opus for everything. |
| GREGAI-11 | P1 | Add **prompt caching** on the system block once the prompt exceeds the model's cacheable minimum. | Cost/latency win once tools + student profile inflate the system prompt past ~4096 tokens. |

## Cross-cutting constraints

- **Privacy**: GREGAI-09 (and any chat-review feature) requires an explicit update to the privacy policy — students must know chats may be reviewed. Minors are the user base.
- **Cost**: Every feature that grows tokens (06, 07, 08) interacts with GREGAI-10/11 — plan them together.
- **Serverless**: Persisted counters/quotas (GREGAI-02) must live in Mongo, not the in-memory `ratelimit.server.ts` store.
- **Auth**: All new endpoints reuse `getUserId()` (now Google-aware) + the CSRF/rate-limit patterns already established.
