**Update `app/utils/stripe.server.ts` - `handlePaymentSuccess()` function:**

1. **Add idempotency check** at the top of the function, after the Stripe null check:
   ```typescript
   // Idempotency: check if already processed
   const existingPurchase = await prisma.purchase.findFirst({
     where: { stripeSessionId: sessionId, status: 'completed' },
   });
   if (existingPurchase) return; // Already fulfilled — safe to return
   ```
   Place this BEFORE the `stripe.checkout.sessions.retrieve()` call to avoid unnecessary Stripe API calls.

2. **Set tokenExpiresAt** when updating the purchase to completed. Calculate 365 days from now:
   ```typescript
   const tokenExpiresAt = new Date();
   tokenExpiresAt.setDate(tokenExpiresAt.getDate() + 365);
   ```
   Add `tokenExpiresAt` to the `data` object in the `prisma.purchase.update()` call:
   ```typescript
   await prisma.purchase.update({
     where: { id: purchaseId },
     data: {
       status: 'completed',
       stripePaymentId: session.payment_intent as string,
       tokenExpiresAt,
       updatedAt: new Date(),
     },
   });
   ```
   Note: The existing code does NOT set `updatedAt` — add it.

**Update `app/utils/stripe.server.ts` - `verifyDownloadToken()` function:**

3. **Add download count enforcement** before the download count increment:
   ```typescript
   // Check download limit
   if (purchase.downloadCount >= purchase.maxDownloads) {
     return null;
   }
   ```

4. **Add token expiration check:**
   ```typescript
   // Check token expiration
   if (purchase.tokenExpiresAt && purchase.tokenExpiresAt < new Date()) {
     return null;
   }
   ```

5. **Add book.isActive check** after fetching the book:
   ```typescript
   if (!book || !book.isActive) {
     return null;
   }
   ```
   The existing code checks `if (!book)` — extend it to also check `!book.isActive`.

6. **Reorder the function** so checks happen BEFORE the increment:
   The final order should be:
   1. Find purchase by token
   2. Check purchase exists and status is 'completed'
   3. Check downloadCount < maxDownloads
   4. Check tokenExpiresAt is not expired
   5. Find book
   6. Check book exists and isActive
   7. Increment downloadCount
   8. Return book info

**Update `app/routes/api.stripe-webhook.tsx`:**

7. **Replace `json()` with `data()` from `@remix-run/node`:**
   - Change import: `import { ActionFunction, json } from '@remix-run/node'` → `import { type ActionFunction } from '@remix-run/node'; import { data } from '@remix-run/node';`
   - Replace all `json(...)` calls with `data(...)` throughout the file. This aligns with the v3_singleFetch flag enabled in the project.
   - There are 5 `json()` calls to replace: the 405 response, 400 missing sig, 400 invalid sig, the success 200, and the 500 error.

Important: The webhook must always return a 200-level response quickly so Stripe doesn't retry. The idempotency check ensures that even if Stripe sends the same event twice, the handler returns cleanly. Do NOT add CSRF or rate limiting to the webhook — Stripe signature verification is the auth mechanism.
