   - After the existing `alreadyPurchased` check, add:
   ```typescript

   ```
   - Modify the return statement to include `csrfToken` in data and merge CSRF headers:
   ```typescript
   return data(
     { book: localizedBook as unknown as Book, isLoggedIn, stripeEnabled: isStripeConfigured(), locale, alreadyPurchased, csrfToken },
     { headers: csrfHeaders }
   );
   ```

4. **Harden the action function:**
   At the top of the action (after the bookId null check), add in this order:

   a. **CSRF validation:**
   ```typescript
   const csrfError = await requireCSRFToken(request);
   if (csrfError) return csrfError;
   ```

   b. **Auth check** (already exists — keep as-is)

   c. **Rate limiting** (after the auth check, using user.id):
   ```typescript
   const rateLimitResponse = applyRateLimit(request, 'api', user.id);
   if (rateLimitResponse) return rateLimitResponse;
   ```

   d. **Audit logging** (after rate limit check, before the try/catch):
   ```typescript
   const { ipAddress, userAgent } = getClientInfo(request);
   await logAuditEvent({
     userId: user.id,
     action: 'purchase',
     resource: 'book',
     resourceId: bookId,
     ipAddress: ipAddress ?? undefined,
     userAgent: userAgent ?? undefined,
   });
   ```

5. **Add CSRF hidden input to the purchase form:**
   In the component, destructure `csrfToken` from `useLoaderData<LoaderData>()`. Add `useActionData` hook: `const actionData = useActionData<{ error?: string }>()`.

   Inside the `<Form method="post">`, before the submit button, add:
   ```tsx
   <input type="hidden" name="_csrf" value={csrfToken} />
   ```

6. **Add error display from actionData:**
   Below the `<Form>` closing tag (but inside the same conditional block), add:
   ```tsx
   {actionData?.error && (
     <div className="mt-4 p-4 bg-red-50 border border-red-200 rounded-lg">
       <p className="text-red-700 text-sm">{actionData.error}</p>
     </div>
   )}
   ```

Important: The `requireCSRFToken()` clones the request internally via `request.clone().formData()`, so it won't consume the request body. The existing action doesn't read formData (only `params.bookId`), so no conflict. The rate limit uses `'api'` type (100/min) which is appropriate for purchase attempts.
