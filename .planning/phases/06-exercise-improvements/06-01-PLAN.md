<objective>
Reshape the Exersice data model and data-access layer so downstream plans (bulk upload, public search) can rely on typed, consistent category/level/type/tags filtering. Additionally, relocate the Pagination component to `components/shared/` so Wave 2 plans 06-02 and 06-03 can both import it without a parallel-write conflict.

Purpose: The existing `tags: String` field stores a single comma-separated string that mixes level ("Α-Λυκείου"), type ("Λυμένες ασκήσεις"), and free-form extras. Legacy rows drifted from the `TAGS`/`Type`/`Category` allowlists in `services/models/models.ts`, breaking search. Splitting level/type into dedicated fields and migrating tags to `String[]` aligns Exersice with Book/Video (which already use `String[]`) and enables native Prisma array queries. Moving the Pagination component out of `components/admin/` lets the public exercises page (Plan 06-03) reuse it without a Wave-2 race with the admin route (Plan 06-02) that also imports it.

Output:
- Prisma schema change committed and pushed (`prisma db push`)
- One-time migration script that parses legacy `tags` strings into `{level, type, tags[]}`
- `getPaginatedExercises` extended to accept `{category?, level?, type?, text?, lang?}` and apply filters server-side
- `validateExerciseFields` extended to validate `level` and `type` against the Greek allowlists
- `components/shared/Pagination.tsx` (canonical) + `components/admin/Pagination.tsx` (re-export shim)
</objective>
