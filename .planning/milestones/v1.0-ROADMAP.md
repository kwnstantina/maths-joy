# Milestone v1.0: Book Platform

**Status:** ✅ SHIPPED 2026-03-17
**Phases:** 1-2
**Total Plans:** 5

## Overview

Complete book e-commerce pipeline for the GregKyrMaths platform — admin uploads books with metadata, students browse/filter catalog, purchase via Stripe with EU VAT, and download with count/expiry enforcement.

## Phases

### Phase 1: Book Upload

**Goal**: Admin can build and manage a book catalog with full metadata and file assets
**Depends on**: Nothing (existing auth and Cloudinary integration handle prerequisites)
**Requirements**: BOOK-01
**Plans**: 2 plans

Plans:
- [x] 01-01-PLAN.md — Schema extension, streaming Cloudinary upload, book data layer refactor (soft delete, archive)
- [x] 01-02-PLAN.md — Admin book management route, upload form, card grid with inline editing, i18n

**Details:**
- Extended Book Prisma model with authorName, pageCount, isbn, edition, discountPrice, deletedAt, archivedPdfIds, thumbnailPublicId
- Streaming upload via uploadStreamToCloudinary (writeAsyncIterableToWritable)
- Soft delete replacing hard delete; PDF archive-on-replace via archivedPdfIds
- Admin route at /admin/books with multi-action handler (_action discriminator)
- BookCard with inline editing via useFetcher, active/inactive toggle
- Full Greek/English i18n for admin.books.* namespace

### Phase 2: Book Commerce

**Goal**: Students can find, purchase, and download math books through a complete Stripe payment flow
**Depends on**: Phase 1
**Requirements**: BOOK-02, BOOK-03, BOOK-04, BOOK-05
**Plans**: 3 plans

Plans:
- [x] 02-01-PLAN.md — Catalog category filtering + purchase action security (CSRF, rate limiting, audit, Stripe Tax, metadata)
- [x] 02-02-PLAN.md — Checkout success page with backend payment verification, Cloudinary URL, useRevalidator polling
- [x] 02-03-PLAN.md — Webhook idempotency + download enforcement (count limits, token expiry, rate limiting)

**Details:**
- Category filter via URL search params with pill-style Link buttons
- Purchase action security: CSRF → auth → rate limit → audit → business logic
- Stripe Tax enabled with digital book tax code (txcd_10010001) for EU VAT
- Checkout success page verifies payment via Stripe API (backend truth)
- useRevalidator polls every 2s for webhook confirmation
- Idempotent webhook: checks DB before Stripe API call
- Download enforcement: status → count → expiry → book active → increment
- IP-based rate limiting (20/hr) on unauthenticated download route
- Purchases page shows remaining downloads, hides button when exhausted

## Milestone Summary

**Key Decisions:**
- Used Prisma.InputJsonValue for translation field (fixes pre-existing type error)
- PDF archive uses two-step Prisma update for safe array push
- Multi-action handler pattern (_action field) for admin routes
- Link-based category filter for Remix consistency
- cloudinaryUrl used directly (books have public access_mode)
- Download count incremented on URL generation, not click
- Webhook idempotency: DB check before Stripe API call
- IP-based rate limiting for unauthenticated download route

**Issues Resolved:**
- ESLint structuredClone incompatibility (pre-existing, worked around)
- Pre-existing TypeScript errors in uploadEx.tsx, video.prisma.ts (out of scope)

**Issues Deferred:**
- Remaining requirements (Q&A, Video, Exercises, i18n) moved to v1.1

**Technical Debt Incurred:**
- Books use public Cloudinary URLs (not signed) — acceptable for current access model
- Download count increments on URL generation, not actual download click
