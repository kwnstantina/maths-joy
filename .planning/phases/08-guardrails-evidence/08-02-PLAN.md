No CSRF — the sibling greg-ai JSON APIs don't use it (they authenticate via `getUserId` + rate limit); stay consistent.

    ```ts
    import type { ActionFunctionArgs } from "@remix-run/node";
    import { json } from "@remix-run/node";
    import { getUserId } from "~/utils/auth.prisma";
    import { setMessageRating } from "~/utils/gregChat.prisma";
    import { applyRateLimit } from "~/utils/ratelimit.server";

    interface FeedbackBody {
      messageId?: unknown;
      rating?: unknown;
    }

    export async function action({ request }: ActionFunctionArgs) {
      const userId = await getUserId(request);
      if (!userId) {
        return json({ error: "Unauthorized" }, { status: 401 });
      }

      if (request.method !== "POST") {
        return json({ error: "Method not allowed" }, { status: 405 });
      }

      const rateLimitResponse = applyRateLimit(request, "api", userId);
      if (rateLimitResponse) {
        return rateLimitResponse;
      }

      let body: FeedbackBody;
      try {
        body = (await request.json()) as FeedbackBody;
      } catch {
        return json({ error: "Invalid JSON" }, { status: 400 });
      }

      const messageId = typeof body.messageId === "string" ? body.messageId : "";
      const rating = body.rating === 1 || body.rating === -1 ? body.rating : null;
      if (!messageId || rating === null) {
        return json({ error: "Invalid input" }, { status: 400 });
      }

      const result = await setMessageRating(messageId, userId, rating);
      if (!result.ok) {
        return json({ error: "Message not found" }, { status: 404 });
      }

      return json({ ok: true, rating: result.rating });
    }

    export async function loader() {
      return json({ error: "Method not allowed" }, { status: 405 });
    }
    ```

    The `rating` in the response is `setMessageRating`'s toggled truth (may be `null` when the click cleared an existing rating) — the widget reconciles its optimistic state against this value.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/greg-ai | Untrusted student input (message, sessionId) crosses into the chat + quota logic |
| browser → /api/greg-ai/feedback | Untrusted `{ messageId, rating }` crosses into the rating write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering / Elevation (IDOR) | feedback route setMessageRating | mitigate | Ownership enforced in setMessageRating: `where: { id, role: "assistant", session: { userId } }` — a user cannot rate another user's message; returns 404 |
| T-08-02 | Tampering | feedback route rating input | mitigate | Reject any rating not strictly `1` or `-1` before the DB write (400) |
| T-08-03 | Denial of Service / cost | chat endpoint quota | mitigate | Mongo daily cap (50) after the in-memory burst limiter; atomic upsert+increment prevents concurrent overshoot; 429 on exceed |
| T-08-04 | Spoofing | both routes | mitigate | `getUserId(request)` → 401 before any work; identifier for rate-limit is the authenticated user id |
| T-08-05 | DoS (rating spam) | feedback route | mitigate | `applyRateLimit(request, "api", userId)` (100/min) gates rating writes |
| T-08-06 | Information disclosure | 429 body | accept | Body is a static error code `daily_limit_reached`; no user data or exact counts leaked |
</threat_model>
