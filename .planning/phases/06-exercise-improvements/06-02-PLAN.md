<objective>
Let the admin upload many exercise PDFs in one operation without sacrificing the security chain or the single-upload flow.

Purpose: Greg currently uploads exercises one at a time. For a new textbook chapter (20+ PDFs) this is painful. Bulk upload is EX-01. The existing single-upload action has a mature streaming Cloudinary pipeline, CSRF/rate-limit/audit chain, and i18n-aware form — we extend that pattern to a multi-file action rather than rewriting it. We also close the 06-01 gap by exposing `level` and `type` dropdowns in the single-upload form so new exercises are created with the new fields populated.

**Transient-state note (expected, not a regression):** Between the merge of Plan 06-01 and the completion of this plan's Task 2 step 1.d, `app/routes/admin.exercises.tsx` will show TypeScript errors referencing `tags: string` (because 06-01 changed the data layer to `tags: string[]` without touching the route). Those errors are introduced by 06-01 intentionally and are cleared by this plan's Task 2 step 1.d. Do NOT treat them as a blocker before reaching that step.

Output:
- New admin UI component `BulkExerciseUploadForm` with multi-file picker + shared metadata + per-file title override + per-file result panel
- New exercise-specific `ExerciseCategorySelect` that renders category + level + type + tags-extra (preserving the generic `CategorySelect` for Video / Training upload forms)
- New `createExerciseBulk` action branch in `admin.exercises.tsx`, partial-success-with-retry-list semantics
- Single `ExerciseUploadForm` switched to `ExerciseCategorySelect` so level + type are first-class fields on the single form
- New i18n keys for bulk upload UI in both locale files
</objective>
