  <action>
Modify `app/utils/qa.server.ts` with these four changes:

**1. Wrap voteQuestion in prisma.$transaction:**
Replace the current voteQuestion implementation with an interactive transaction. The function signature stays the same but internally uses `prisma.$transaction(async (tx) => {...})`. All findUnique, create, update, delete calls inside use `tx` instead of `prisma`. The three vote scenarios (toggle off, flip, new vote) each atomically update the vote record AND the question.voteCount in the same transaction. Return `{ action: 'removed' | 'changed' | 'added', newValue: number }`.

**2. Wrap voteAnswer in prisma.$transaction:**
Same pattern as voteQuestion but for answer votes. Uses `tx.answerVote` and `tx.answer` inside the transaction.

**3. Add self-vote prevention to both vote functions:**
Add a `selfCheck` parameter or query the question/answer to get the authorId. Before processing the vote, check `userId !== authorId`. If they match, throw an error: `throw new Error('Cannot vote on own content')`. For voteQuestion: query `tx.question.findUnique({ where: { id: questionId }, select: { authorId: true } })`. For voteAnswer: query `tx.answer.findUnique({ where: { id: answerId }, select: { authorId: true } })`.

**4. Fix deleteQuestion to clean up AnswerVotes:**
In `deleteQuestion`, before deleting answers, query all answer IDs: `const answers = await prisma.answer.findMany({ where: { questionId: id }, select: { id: true } })`. Then delete all AnswerVotes for those answers: `await prisma.answerVote.deleteMany({ where: { answerId: { in: answers.map(a => a.id) } } })`. Do this BEFORE the existing answer delete. Wrap the entire delete sequence in a $transaction for atomicity.

**5. Add sortBy parameter to getQuestions:**
Change signature to: `getQuestions(filters: QuestionFilters = {}, page = 1, limit = 20, sortBy: 'newest' | 'votes' = 'newest')`. Update the `orderBy` clause: if sortBy is 'votes', use `{ voteCount: 'desc' }`, otherwise keep `{ createdAt: 'desc' }`.

**Create `components/qa/VoteButtons.tsx`:**

A reusable component for question and answer voting with useFetcher and optimistic UI.

Props interface:
```typescript
interface VoteButtonsProps {
  type: 'question' | 'answer';       // determines _action value: 'voteQuestion' | 'voteAnswer'
  targetId: string;                    // questionId or answerId
  voteCount: number;                   // current count from loader
  userVote: number;                    // 0, 1, or -1 (current user's vote)
  csrfToken: string;                   // CSRF token from loader
  disabled?: boolean;                  // true for own content or logged-out users
}
```

Implementation:
- Use `useFetcher()` from `@remix-run/react`
- Derive optimistic state: when `fetcher.formData` exists (submission pending), calculate optimistic vote count and user vote from the pending form data using a pure helper function `calculateOptimisticCount(currentCount, currentUserVote, newVoteValue)`. When fetcher is idle, fall back to props.
- Render as a vertical stack: upvote button (arrow up), vote count, downvote button (arrow down)
- Each button is inside a `fetcher.Form` with method="post", containing hidden inputs for `_csrf`, `_action` (e.g., "voteQuestion"), `targetId`, and `value` (1 or -1)
- Active vote state: upvote button highlighted (text-green-600) when user voted +1, downvote highlighted (text-red-600) when user voted -1
- Disabled state: buttons show `opacity-50 cursor-not-allowed` when `disabled` prop is true or during submission
- Export the `calculateOptimisticCount` helper function as well (for potential testing)
